# Local Mother API

Run `npm start` from the project root. The API listens only on `127.0.0.1:3001` by default. `PORT` and `HOST` configure the listener. The built frontend is served from `dist/`; during development Vite proxies `/api` to this service.

- `GET /api/health`: service readiness.
- `GET /api/models`: installed models from Ollama at `http://127.0.0.1:11434`. No remote model hosting or paid API is used.
- `POST /api/chat`: `{model, messages: [{role: "user" | "assistant", content}], context?: string}`. Returns `{message: {role: "assistant", content}, model, engine: "ollama", neural: true}`. Requires a running Ollama instance and an installed compatible model. Model absence is an explicit error; there is no simulated neural response.
- `POST /api/datasets/inspect`: `{url}`. Downloads at most 2 MiB of public HTTPS UTF-8 JSON, JSONL, CSV, or text for review. Returns source URL, SHA-256, raw bounded preview, record metadata, and warnings. Downloads never execute content, update weights, or auto-approve sources.

Dataset URLs block local and reserved addresses, credentials, non-HTTPS protocols and nonstandard ports. In direct-network mode every DNS answer is checked and the TLS connection pins a validated address. In proxy-only cloud environments, where local public DNS is unavailable, an alternative route uses the configured HTTPS proxy only for the established dataset hosts `raw.githubusercontent.com`, `huggingface.co`, and `archive.ics.uci.edu`. This route requires Node 24.5+ and delegates destination DNS to the managed proxy; it does not independently pin destination addresses. Arbitrary domains cannot use that fallback, and a hostname that actually resolves to a private address remains blocked. Every redirect repeats these checks. TLS verification stays enabled, response size is bounded while streaming, and total fetch time is bounded. HTTPS and hashing establish transport integrity and provenance of these bytes; they cannot verify that statements are true or datasets are licensed.

The API has no permissive CORS and rejects cross-origin state-changing requests. It also checks every request’s `Host` header to prevent browser DNS-rebinding attacks against the local model: localhost and literal IP addresses are accepted; all other DNS hostnames must be explicitly configured in `MOTHER_ALLOWED_HOSTS` as comma-separated exact names, for example `MOTHER_ALLOWED_HOSTS=mother.example.org,dev.example.org`. Schemes, ports, paths and wildcards are not permitted in this setting. A cloud/platform reverse proxy that preserves a custom hostname needs that hostname configured before use. Vite’s localhost proxy works without additional settings. Treat `HOST=0.0.0.0` as explicitly exposing this unauthenticated prototype to a trusted local network. It is not suitable for public Internet hosting without authentication, TLS termination, rate limits, and deployment hardening. No endpoint executes shell commands, scans arbitrary networks, or controls devices.

Run `node --test server/*.test.js` for security and API tests. Tests mock Ollama; they validate integration behavior without claiming an actual model is installed.

Verified in this cloud environment: the real public cars dataset at `https://raw.githubusercontent.com/vega/vega-datasets/main/data/cars.json` downloaded through the configured HTTPS proxy, parsed as 406 JSON records (100,492 bytes), and produced SHA-256 `f686a53678b21f4231e2f6a5ba7ce5761d9d39204fccdea1caa29fb8c460e319`. This verifies the download-and-inspect pipeline, not factual accuracy of the source.
